« THE ID », COURT, ABRÉGÉ ET LONG — 3 octobre
==============================================

L'ÉCART ANNONCÉ ÉTAIT FAUX. Le relevé du polygone (2 octobre) et les notes de
la 0.7.7 et de la 0.7.8 disaient : « the long id of button 2 » rend « 5 »
dans HC, là où HyperCard rend « card button id 5 of card id … of stack … ».
La seconde moitié n'avait JAMAIS été mesurée : c'était un souvenir, écrit
comme un fait. Mesuré le 3 octobre, HyperCard rend le nombre, comme HC.


MESURÉ DANS HYPERCARD (Basilisk II), par l'utilisatrice
-------------------------------------------------------

Un bouton (id 3) et un champ de carte (id 1) sur une carte de la pile
« test5 », écrit par le script du bouton dans le champ :

    id: 3
    short id: 3
    abbr id: 3
    long id: 3
    card id: card id 2865
    card short id: 2865
    card long id: card id 2865 of stack "Saved HD:More Stacks:Alternate Home Stacks:Home (Small):test5"
    bg id: 2703
    bg long id: 2703
    fld long id: 1

Et deux refus, chacun arrêtant le script :

  · « put the long id of me into x » puis « the name of x » : HyperCard ne
    comprend pas. Une variable qui contient un descripteur ne devient pas un
    objet dans « the … of ».
  · « the long id of this stack » : HyperCard ne comprend pas. Le texte du
    message : non relevé.

Second banc, même jour, deux cartes, x valant « the id of this card » pris
sur la carte 1 ; le champ, recopié par l'utilisatrice :

    card abbr id: card id 2865
    card 2 id: card id 3805
    go x -> card 1
    go card id x -> card 2

  · l'id ABRÉGÉ d'une carte est sa forme par défaut, « card id N » ;
  · une carte qui n'est pas la carte courante se décrit de même ;
  · « go x » ramène sur la carte 1 : le descripteur entier se relit ;
  · « go card id x » ne bouge PAS (on reste sur la carte 2), et la ligne
    suivante s'écrit : le script a continué. L'utilisatrice a vu « expect a
    number here » ; de QUELLE ligne il vient, et s'il est une boîte ou the
    result : non relevé. « card id » n'accepte pas le descripteur entier.

  Conséquence pour HC : plusieurs de nos harnais écrivent « card id » suivi
  de l'id d'une carte — navtest (« card field "data2" of card id
  sortieCarte », « go to card id ident »), pilereelle (« card id n + 0 ») —,
  ce qu'aucune pile d'HyperCard ne peut faire marcher. Ils ne témoignent que
  de l'écart.

  · « send "teste" to y », y valant le long id du bouton : y vaut 3, et le
    gestionnaire « teste » n'écrit rien. HC, même script : « destinataire
    introuvable », PUIS le script continue. Ce que fait HyperCard après
    l'échec — boîte et arrêt, ou silence : non relevé.

Ce qui en ressort :
  · un BOUTON, un CHAMP et un FOND rendent le nombre nu, quel que soit
    l'adjectif ;
  · seule la CARTE se décrit : « card id N » par défaut, le nombre en court,
    et « … of stack "chemin complet" » en long ;
  · une pile n'a pas d'id.

LA CORRECTION — 3 octobre, sur l'accord de l'utilisatrice
--------------------------------------------------------

obj_prop_read (hc_core.c) : l'id d'une CARTE rend « card id N » par défaut
et en abrégé, le nombre en court, « card id N of stack "…" » en long — la
pile écrite comme la met déjà « the long name ». Le reste ne bouge pas.

Le harnais idcarte rejoue les deux bancs ; « go x » y ramène sur la carte 1,
le long id aussi, et « card id (the short id of …) » marche.

Trois harnais écrivaient « card id » suivi de « the id of this card » —
navtest (via navharn, navharn2, navharn3) et pilereelle — : ils passent à
« the short id », comme l'écrirait l'auteur d'une pile d'HyperCard. Trois
témoins changent de la seule forme mesurée (fn, longname, valeur).

Ce qui reste DIFFÉRENT, et voulu ou non mesuré :
  · le CHEMIN de la pile est celui de macOS (« /Volumes/Saved HD/… »),
    comme dans « the long name » depuis qu'il porte un chemin ; HyperCard
    écrivait le chemin à deux-points du vieux Mac OS ;
  · « the long id of this stack » : voir « LA PILE », plus bas.


LA PILE — 3 octobre
-------------------

Le texte du refus, rapporté par l'utilisatrice DANS HYPERCARD, en deux
messages successifs : « can't understand argument of id », puis « can't get
this property ». Lequel vient de quelle tournure — the long id seul, ou un
autre essai — : non relevé. Les deux disent la même chose : refus, et arrêt.

HC rendait 1. Il refuse maintenant toute forme de l'id d'une pile —
« propriété inconnue », dans la langue de ses autres messages — et le
script s'arrête (harnais idcarte, section 5). Les formes courte, abrégée et
nue n'ont pas été jouées dans HyperCard : refusées avec la longue, non
mesurées.

-------------------------------------------

Venu de la pile d'aide d'Apple, « HyperCard Help », convertie par
l'utilisatrice : whereICameFrom y fait

    push recent card
    pop card into theCard
    return theCard

et cardToStackName en tire le nom de la pile d'où l'on vient. HC répondait
« ne sait pas faire » aux deux lignes.

MESURÉ DANS HYPERCARD (Basilisk II), par l'utilisatrice, pile test6, depuis
un bouton de la carte 3 — go card 1, go card 3, push recent card, pop card
into x :

    pop into : card id 2850 of stack "Saved HD:More Stacks:Alternate Home Stacks:Home (Small):test6"
    carte : 3
    carte 1 : 2850          (the short id of card 1, relevé ensuite)

  · « recent card » est la carte d'où l'on vient ;
  · « pop card into » dépile SANS se déplacer — on reste sur la carte 3 ;

section 6. « before » et « after » suivent la grammaire de put : NON MESURÉS
dans HyperCard. Ce que fait « push recent card » sans carte précédente : NON
MESURÉ ; HC n'empile rien et rend « No such card ».


CANTMODIFY — 4 octobre, MESURÉ, PUIS CORRIGÉ LE MÊME SOIR
--------------------------------------------------------

La même pile d'aide lit et pose « the cantModify of this stack ». HC :
« propriété inconnue ».

MESURÉ DANS HYPERCARD, pile test6 :

    set the cantModify of this stack to true
    put the cantModify of this stack into v       -- v = true
    put "essai" into card field 1                  -- RIEN : le champ ne change pas
    set the cantModify of this stack to false

  · la propriété se pose et se lit ;
  · une pile verrouillée REFUSE qu'un script écrive dans un champ, EN
    SILENCE : pas de message, et le script continue — « ça s'exécute mais il
    n'y a rien dans le champ ».

La propriété n'est pas venue seule : une propriété qui se lit sans rien
verrouiller serait « le verrou qui ne ferme rien » que hc_core.h refuse pour
cantDelete sur la pile. Elle est donc arrivée AVEC le verrou mesuré, posé aux
deux endroits par où un script écrit dans un champ — v3_ecrit_objet (« put …
into card field 1 ») et la branche « champ » de container_set, où finissent
toutes les écritures par morceau. Refus silencieux, comme dans HyperCard.
Enregistrée dans notre format (« cantmodify », seulement si posée). Harnais
verrou : le banc rejoué, les morceaux, l'aller-retour par le fichier.

NON MESURÉ, DONC NON VERROUILLÉ : une propriété posée, un bouton créé ou
supprimé, la peinture, et la frappe de l'utilisateur dans un champ d'une
pile verrouillée ; le cadenas qu'HyperCard montre dans la barre des menus ;
et le bit du format d'Apple qui porte le verrou — une pile d'origine
verrouillée s'importe libre.


LA PILE D'AIDE D'APPLE, LE RESTE — 4 octobre
--------------------------------------------

Les autres lignes où « HyperCard Help » convertie s'arrêtait, DANS HC :

  · show menuBar / hide menuBar, show groups / hide groups : « ne sait pas
    faire ». Ce sont des réglages d'affichage : le noyau les accepte et les
    transmet à l'hôte (« menuBar », « showGroups »). HCview.m cache la barre
    des menus SOUS SA FORME DOUCE — elle revient au passage de la souris,
    avec le Dock, AppKit refusant la barre cachée seule ; HyperCard la
    cachait pour de bon : différence voulue. HCtext.m souligne de gris épais
    le texte de style « group » tant que show groups vaut. Rendu NON MESURÉ,
    ni dans HyperCard ni dans HC.
  · « set cmdChar of menuItem … » : propriété de menu inconnue. Le raccourci
    se pose, se lit, et devient la touche ⌘ de l'article.
  · LES TROIS « MENU INTROUVABLE » N'ÉTAIENT PAS DUS À « show menuBar », comme
    je l'avais lu d'abord : le harnais aidemenus les a gardés une fois show
    menuBar accepté. La cause : « menu gHMnu », une VARIABLE qui contient un
    NOM. L'analyseur range une expression comme un rang, et la recherche par
    rang ne trouvait pas « Reference ». create menu passait (il évalue le
    nom), toute référence ensuite échouait. Une valeur qui n'est pas un
    nombre se cherche maintenant par son nom — pour menu, et pour menuItem,
    le site jumeau.

Harnais aidemenus : la forme des gestionnaires de l'aide (addHelpMenu,
toggleActiveText, whereICameFrom, checkCantModify), sans leur texte — la
pile d'Apple n'entre pas dans le dépôt.

« RUN THE SCRIPT » : DRAW MULTIPLE ET LES TROIS FENÊTRES — 5 octobre
--------------------------------------------------------------------

Le bouton « Run the Script » de « HyperTalk Reference » range, avant de
jouer un exemple, l'état de la peinture et des fenêtres d'HyperCard, puis le
remet. DANS HC (l'application), relevé par l'utilisatrice :

    propriété inconnue : multiple
    propriété inconnue : multiSpace
    objet introuvable : it (× 6)

DRAW MULTIPLE est fait pour de bon, pas seulement nommé : « the multiple »
et « the multiSpace » (1 à 100, 1 par défaut, ramené dans ses bornes comme
polySides) se lisent et se posent, l'article « Draw Multiple » entre dans le
menu Options avec sa coche et « doMenu ». Ligne, rectangle, rectangle
arrondi, ovale et polygone régulier laissent alors une copie gravée chaque
fois que la forme a avancé de multiSpace pixels — à la souris, et par
« drag », qui pose ses copies sur le chemin. L'écart compté est le plus grand
des deux déplacements du point tiré. Tout cela est dans HCview.m : compilé
par l'intégration, NON EXÉCUTÉ ici, et l'espacement exact des copies chez
HyperCard N'EST PAS MESURÉ.

LES SIX « it » : la démonstration met dans une variable le MOT-CLÉ de chaque
fenêtre — « tool window », « pattern window », « message window » — et lit,
puis repose, « the visible of it » et « the loc of it ». Le noyau reconnaît
maintenant ces mots-clés, écrits en clair comme dans une variable, et pose la
question à l'hôte sous les noms qu'ils ont chez HyperCard : « Tools »,
« Patterns », « Message ». « window "Tools" » désigne donc la même. L'hôte
sert visible, loc (le coin haut-gauche du contenu, en coordonnées d'écran,
comme la Navigator), rect, name, show, hide et close. La loc qu'HyperCard
rend pour ces palettes N'EST PAS MESURÉE ; ce qui compte pour la
démonstration est qu'une loc relue se repose au même endroit.

TROIS DÉFAUTS PLUS ANCIENS, trouvés en mesurant :

  · « show msg », « hide message box » : « objet introuvable ». Les piles
    d'époque l'écrivent dans presque chaque openStack. La boîte de messages
    est maintenant aussi une fenêtre, pour show, hide et ses propriétés ; elle
    reste un conteneur pour put et les morceaux. boitemsg.c inscrivait
    « the visible of msg » comme chantier restant : son témoin change.
  · « set the loc of window "Navigator" to 10,20 » posait « 20 » : seul le
    dernier élément de la valeur était lu. fenetres.c l'écrivait entre
    guillemets et ne pouvait pas le voir.
  · « choose tool 3 », la forme par le numéro que donne la référence, était
    une faute de syntaxe. Le numéro suit la palette d'HyperCard, de gauche à
    droite et de haut en bas (browse, button, field / select, lasso,
    pencil / … / text, regular polygon, polygon) ; hors de 1 à 18, « No such
    tool ».

Harnais runscript : la forme des gestionnaires de la démonstration, dont la
boucle sur « tool window,pattern window,message window ».

UN ÉCART NOTÉ, PAS CORRIGÉ : par « drag », une forme pleine est remplie SANS
contour ; à la souris, remplie ET entourée. Les deux chemins disent la même
chose de « filled » et ne la font pas pareil. Ce que fait HyperCard n'est pas
mesuré ici : à proposer avec un banc.


GO CARD … OF STACK « HELP EXTRAS » : LA PILE PAS ENCORE OUVERTE — 5 octobre
--------------------------------------------------------------------------

La pile d'aide d'Apple écrit

    go card theIndexName of stack "Help Extras" in a new window -- ∆

et DANS HC (l'application), « HC comprend pas ». Mesuré dans le noyau : la
même ligne marche si « Help Extras » est DÉJÀ ouverte, avec ou sans « in a
new window ». Sinon, « objet introuvable » et le script s'arrêtait.

LA CAUSE : « go stack "X" » demandait à l'hôte d'ouvrir la pile
(v3_va_pile) ; nommer une carte DANS cette pile passait par hct_resout, qui
ne cherche que parmi les piles ouvertes. La correction ouvre la pile d'abord,
par le même hôte, puis résout la carte. Cocoa donne une fenêtre à toute pile
qu'il ouvre : « in a new window » est donc déjà ce qui se passe. Une pile
introuvable donne maintenant « pile introuvable » et « No such stack », et le
script continue — comme « go stack ».

L'hôte cherche le FICHIER à côté de la pile courante, à côté de l'application
et dans Documents, sous « Help Extras » ou « Help Extras.stack » : la pile
doit avoir été convertie et rangée là.

Harnais aidemenus, section 8. Les sections 6 et 7 libéraient des piles sans
les retirer du registre, ce que l'hôte fait toujours (Hcdocument.m) : la
section 8 tombait sur l'adresse morte. Le harnais respecte le contrat.

NON MESURÉ DANS HYPERCARD : « go card "Zut" » vers une carte absente. HC
arrête le script sur « objet introuvable » ; HyperCard, de mémoire, pose
« No such card » dans the result et continue. À vérifier par un banc avant
d'y toucher.


GO CARD theSection & theTopic — 5 octobre
-----------------------------------------

Dans « Help Extras » (Apple), chaque clic sur un sujet fait

    go card theSection & theTopic

et HC répondait « objet introuvable ». L'analyseur lit
« (card theSection) & theTopic » : le rang d'une carte s'arrête avant « & »,
volontairement — « the name of card 1 && the name of card 2 » doit garder son
second terme. Derrière GO, seule la lecture d'Apple a un sens : go ne
concatène rien. v3_cmd_go prend donc toute la concaténation comme NOM de la
carte (& colle, && met une espace) ; un « of stack "X" » en fin de ligne est
repris comme pile, ouverte par l'hôte s'il le faut. Un nom tout en chiffres
est un rang. Carte absente : « carte introuvable », the result « No such
card », et le script continue.

Harnais aidemenus, section 9.

NON MESURÉ DANS HYPERCARD : « put the name of card theSection & theTopic »,
hors de go. HC y garde la lecture de l'analyseur (objet introuvable si aucune
carte ne s'appelle theSection). Et la différence avec « go card "Zut" », qui
arrête encore le script : c'est la question du banc déjà demandé.
