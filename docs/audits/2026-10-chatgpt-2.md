# HC — second defensive review (23 October 2026)

**Scope:** `main` of `cleobuline/hc`, restricted to `HC/hc_origine.c`, `HC/hc_importe.c`, `HC/hc_file.c`, and HyperTalk chunk/evaluation/execution paths in `HC/hct_*.c`. No WebAssembly boundary or object-lifetime claims. Review only; no source changes or PR.

## Result: no qualifying confirmed issue

**CONFIRMED findings: 0.** **NOT REPRODUCED findings reported: 0.**

I did not identify a concrete, realistically sized stack-file or HyperTalk input that I could substantiate as producing an out-of-bounds read/write, undefined integer operation, uncontrolled recursion or loss of saved data in the examined paths. Rather than label theoretical concerns as bugs, this report records the checks observed and the testing gap. **This is not a security sign-off and is not a claim that the entire scope is free of bugs.**

## Specific areas checked

- **`HC/hc_origine.c:1139-1206` — binary block directory.** A block shorter than its header or longer than the remaining file is refused unless the documented high-byte size repair yields a plausible size. The reader records whether the block walk ends exactly at the file end.
- **`HC/hc_origine.c:701-858` — part list.** Part lengths must contain the minimum header and must stay within the enclosing block. Part names are checked for a terminating zero *within the part*, rather than relying solely on the whole-file bounds. Invalid part list lengths lead to failure. No reproducible counterexample was established.
- **`HC/hc_origine.c:860-974` — content records.** Each record's claimed payload length is compared against the enclosing block end. The code distinguishes signed 16-bit part IDs from unsigned lengths. Invalid decoration-range sizes are treated as anomalies rather than blindly used as addresses.
- **`HC/hc_origine.c:990-1020` — layer name and script.** The layer name must terminate within the layer block; the script scan is bounded by that block end. A missing script terminator is not treated identically to a missing name terminator, but I did not demonstrate a memory-safety issue or qualifying data-loss consequence.
- **`HC/hc_file.c:1170-1290` — text stack records.** Truncated hex pairs, malformed icon bytes, excess icon pixels and invalid embedded-module hex cause a load error rather than silently padding or overrunning an icon. Embedded modules are capped by `HC_MODULE_OCTETS_MAX`.
- **`HC/hct_chunk.c:172-253` — chunk ranges.** Character positions advance by UTF-8 sequence lengths; word, item and line spans use bounded searches. Nonpositive ranges have explicit handling; absent end chunks clamp to the input length.
- **`HC/hct_exec.c:560-595` and `HC/hct_chunk.c:339-492` — chunk assignment.** The evaluator rejects nonnumeric/out-of-range indexes, and chunk-writing size calculations check `INT_MAX` before allocating. The previous signed-size issue documented in this code is already addressed.
- **`HC/hc_importe.c` — conversion.** Inspected part-property translation, import allocations and conversion of original paint data; no separately substantiated memory-safety issue identified.
